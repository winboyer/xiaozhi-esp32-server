# LLM 闸门调度方案设计

## 目标

将潮白河兴各庄闸调度方案从确定性模板输出改为每次调用大模型分析；每次请求均向模型提供用户目标、规格书确认的固定工程参数和可获取的监测数据，并要求模型使用固定七段结构返回分析建议。

## 输入上下文

- 用户原始问题和从文本提取的目标过闸流量。
- 固定工程参数：兴各庄闸9孔、单孔净宽35m、翻板式平面钢闸门、闸门高度5m、闸底板顶高程9.00m。
- 监测数据：从 `DataQueryEngine` 中提取最新可用的水位、流量、流速、时间戳、设备名称和安装位置；仅将数据标记为“通用监测数据”而非兴各庄闸数据，除非安装位置或设备名称明确匹配兴各庄闸。
- 当前代码没有9孔实际开度和闸门设备状态的数据库字段。模型提示中必须明确说明该数据未接入，不得虚构。

## 模型输出

模型每次调用均输出以下七个标题，标题必须原样保留：

1. `【1、已知条件和数据】`
2. `【2、推荐的估算方案】`
3. `【3、估算推理过程】`
4. `【4、建议采用的开度估算档位】`
5. `【5、优先推荐方案的原因】`
6. `【6、现场调度步骤】`
7. `【7、最终估算结论】`

模型可以基于当前输入数据推导建议，但必须：

- 明确区分规格书确认参数、实时监测数据和估算假设。
- 没有上游/下游明确点位、实际闸门开度或泄流率定曲线时，指出缺失项及其对建议可靠性的影响。
- 仅输出辅助调度建议，不下发控制指令；标注“需人工复核”。
- 不生成特定单孔编号、固定开度百分比或自动执行结论，除非对应数据在输入上下文中存在。

## 路由与失败处理

- `/api/v1/intent/analyze` 命中闸门方案关键词后，跳过普通数据库意图分类，直接调用 LLM。
- LLM 调用失败时，返回“闸门调度分析服务不可用”及可用的输入数据摘要；不回退到原先的固定七段规则模板。
- 输出用于方案分析与人工复核，不能作为闸门自动控制命令。
