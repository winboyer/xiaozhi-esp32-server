📋 详细处理流程说明

1. 音频采集 → VAD 检测：ESP32 通过 WebSocket 发送音频流，服务端 VAD 模块检测是否有语音活动，过滤静音片段。设备刚被唤醒时短暂忽略 VAD（just_woken_up）。

2. ASR 语音识别：识别后的文本可能包含说话人信息（JSON 格式 {speaker, content}），支持声纹识别区分用户。

3. 唤醒词/退出检查：先检查是否为设备唤醒词或明确的退出命令（如"再见"）。

4. 意图识别 LLM：专用 LLM 分析用户意图，判断是否匹配已注册的工具函数。匹配则输出 function_call JSON（含工具名+参数），不匹配则标记 continue_chat 进入普通对话。

5. 工具调用：ToolManager 将 function_call 路由到对应执行器（服务端插件 / HASS / 设备 IoT 等），执行后返回 ActionResponse（RESPONSE 直接回复 / REQLLM 交由主 LLM 总结 / ERROR 错误处理）。

6. 主 LLM 对话：支持流式输出、多轮记忆、工具递归调用（最大深度 5），通过 direct_answer 虚拟工具防止小模型误触发真实工具。

7. TTS 合成输出：LLM 文本回复经 TTS 合成为音频，分句构建 TTSMessageDTO 队列，通过 WebSocket 回传设备播放。

📋 业务流程说明（面向业务人员）

🔹 整体流程（5 步走）：

  1. 用户开口说话 — 对着智能设备说出你想查什么、想控制什么，就像跟人聊天一样自然。
  2. AI 大脑理解意图 — 系统自动判断你是要查数据（地磅、人员、车牌）还是要控制设备（灯光、空调、音乐），并提取出关键信息（时间、地点、操作）。
  3. 调用对应的业务能力 — 系统匹配到正确的功能后，去对应的系统获取数据或发送控制指令。
  4. 获取/执行结果 — 从地磅系统取回过磅记录、从考勤系统取回打卡数据，或者向智能家居发送开关指令。
  5. 语音播报结果 — AI 把获取到的数据整理成简洁易懂的口语，通过设备扬声器播放出来。

🔹 数据查询场景示例：

用户说的话 系统做什么 语音回复
「三元里今天运了多少车」 查地磅系统 → 统计今日过磅记录 「三元里今天共运输 127 车次，总重量 1850 吨」
「张三今天上班了吗」 查考勤系统 → 获取张三今日打卡情况 「张三今天已打卡，上午 8:03 到岗」
「查下粤A12345的进出记录」 查车牌系统 → 获取该车辆通行历史 「最近一周粤A12345共进出 15 次，最近一次是今天上午 9:20」

🔹 设备控制场景示例：

用户说的话 系统做什么 语音回复
「把客厅灯打开」 向智能家居发送开灯指令 「好的，客厅灯已打开」
「空调调到 26 度」 向智能家居发送温度调节指令 「已将空调设置为 26 度」
「放首歌听听」 向音响发送播放音乐指令 「好的，正在为您播放音乐」

🔹 业务能力可扩展

系统采用插件化设计，数据查询和设备控制的能力可以灵活增减。例如新增「气象数据查询」「门禁控制」「视频监控调取」等能力，只需接入对应的数据源或设备系统即可，无需修改核心框架。
